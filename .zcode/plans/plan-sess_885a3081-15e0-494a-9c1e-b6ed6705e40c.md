## Onboarding walkthrough — implementation plan

A guided first-run onboarding dialog (Welcome → Compose → Export) plus a TopBar help (?) icon to re-open it anytime. Mirrors the codebase's existing `theme.ts` persistence pattern and `ConfirmDialog.tsx` modal pattern.

### New files

**`src/state/onboarding.ts`** — persistence + visibility store
- Mirrors `src/state/theme.ts` exactly: `useSyncExternalStore`, module-level listener set, `STORAGE_KEY = 'composa-onboarding-seen'`, graceful `try/catch` around localStorage (degrades to in-memory in private mode/SSR).
- API:
  - `hasSeenOnboarding(): boolean` — reads the seen flag.
  - `markOnboardingSeen(): void` — sets flag + persists + notifies.
  - `showOnboarding()` / `hideOnboarding()` — control ephemeral "is the dialog open" state (re-openable on demand via the help icon, independent of the persisted flag).
  - `useOnboardingOpen(): boolean` — React hook for subscribers.
- First-run gating lives here: `App.tsx` calls `showOnboarding()` on mount **only if** `!hasSeenOnboarding()`. Marking seen happens on dismiss/finish so the help icon can still re-open it later.

**`src/components/OnboardingDialog.tsx`** — the walkthrough modal
- Models `ConfirmDialog.tsx`: same accessibility pattern (focus-trap, Escape closes, backdrop click closes, `aria-modal`, `role="dialog"`), same visual tokens (`bg-surface`, `border-border`, `text-fg`/`text-fg-muted`), same `composa-dialog-in` keyframe. Rendered in place (no portal), `z-50`.
- 4 steps with `steps[]` array, each `{ title, body, glyph }`:
  1. **Welcome** — what composa is (compose images → export one SVG).
  2. **Compose** — upload a base (sets canvas), then stack overlays; drag/resize directly.
  3. **Arrange** — undo/redo (⌘Z), alignment tools, layer opacity, dark/light toggle.
  4. **Export** — Export button → self-contained SVG; no backend, no tracking.
- Footer: `● ○ ○ ○` progress dots + **Back** / **Next**; on the last step Next becomes **Got it**. `Skip` (top-right ✕ and a Skip link) also closes. On any close path → `markOnboardingSeen()` + `hideOnboarding()`.
- `data-testid`s: `onboarding-dialog`, `onboarding-next`, `onboarding-back`, `onboarding-skip`, `onboarding-dots`.

### Edits

**`src/panels/TopBar.tsx`** — add the help (?) icon button
- Insert a ghost icon button in the control cluster, placed right after the theme toggle (before the divider that precedes Export) so the cluster reads: undo/redo | theme | **help** | export/reset.
- Same ghost-button classes as undo/redo/theme (`p-2 text-fg-muted hover:bg-raised-hover hover:text-fg`, `focus:ring-2 focus:ring-fg-muted/40`), a circled-? SVG, `title="Show onboarding"`, `aria-label="Show onboarding"`, `data-testid="onboarding-help"`.
- `onClick={() => showOnboarding()}` — re-opens regardless of the seen flag (the user's "see it again" requirement). Does **not** reset the seen flag.

**`src/App.tsx`** — mount the dialog + first-run trigger
- Import `OnboardingDialog`, render it after `StatusBar`.
- Add a `useEffect(() => { if (!hasSeenOnboarding()) showOnboarding() }, [])` so genuine first-run users (empty localStorage) get the walkthrough automatically.

**`playwright.config.ts`** — one line to keep the existing suite green
- Add `addInitScript` to the `use` block: `await page.addInitScript(() => { try { localStorage.setItem('composa-onboarding-seen', '1') } catch {} })` so every existing e2e test (fresh context = would otherwise look like a first run) never sees the modal. **No edits to the 6 existing spec files.**

### Tests

**`tests/unit/onboarding.test.ts`** (new) — first-run gating logic
- `hasSeenOnboarding()` defaults to `false` on empty localStorage.
- `markOnboardingSeen()` persists and flips the read.
- `showOnboarding()`/`hideOnboarding()` toggle `useOnboardingOpen()`.
- localStorage-unavailable path (stub `localStorage.setItem` to throw) doesn't crash.
- (Mirrors the style of `tests/unit/sanity.test.ts` / `propertiesForm.test.ts` — plain vitest, jsdom.)

**`tests/e2e/onboarding.spec.ts`** (new) — the "show again" path
- Seed the seen flag (so first-run doesn't auto-open), goto `/`.
- Click `data-testid="onboarding-help"` → `onboarding-dialog` is visible.
- Step through with `onboarding-next`, assert the progress dots and that Back works.
- Finishing (Got it) closes the dialog; the help icon re-opens it again.

### Why this shape
- **Style choice**: multi-step walkthrough over a static card — matches the polished "pro-tool" aesthetic the codebase explicitly cultivates (Figma-like status bar, kbd chips, tooltips) and gives first-timers an engaging 4-beat tour.
- **Trigger**: TopBar help (?) icon per your choice; always re-opens, never resets the seen flag.
- **Persistence**: mirrors the proven `theme.ts` pattern (`composa-*` key convention, `useSyncExternalStore`, graceful degradation) rather than introducing a new state mechanism.
- **Test isolation**: the `addInitScript` seed keeps the 6 existing specs untouched while a dedicated spec + unit tests cover both the trigger and first-run gating.

### Out of scope
- No changes to the composition store, exporter, WASM, or panels beyond the TopBar icon.
- No persistence of *where* in the tour a user is (re-open always starts at step 1) — intentional simplicity.
