## Emerald + Dark/Light redesign for composa

Visual-only redesign: emerald/teal accent on layered neutrals, plus a dark/light toggle. **No behavior, state, layout, component APIs, icon shapes, or test selectors change.** Foundation is a Tailwind v4 CSS-variable token system so both themes are one variable block each — not a class swap.

### Foundation (3 files)

1. **`src/index.css`** *(rewrite)* — the token system:
   - `@import "tailwindcss";`
   - `@custom-variant dark (&:where(.dark, .dark *));` (re-enables class-driven dark mode; v4 defaults to `prefers-color-scheme`, we drive via `.dark` on `<html>`)
   - `:root` (light) + `.dark` variable blocks for ~16 semantic tokens: `--bg`, `--surface`, `--raised`, `--raised-hover`, `--border`, `--border-strong`, `--fg`, `--fg-muted`, `--fg-subtle`, `--primary`, `--primary-strong`, `--primary-fg`, `--accent`, `--danger`, `--danger-fg`, `--warn` (the palette from the design doc, emerald/teal + rose, light/dark variants)
   - `@theme inline { --color-<name>: var(--<name>); }` mapping each var into Tailwind's color namespace so `bg-surface`, `text-fg`, `border-border`, `bg-primary`, `ring-accent`, etc. resolve to live CSS vars and flip with theme (`inline` = live reference, not a build-time copy)
   - Keep the `composa-status-pulse` keyframe + `.status-pulse` (now keyed off `--warn`); add `::selection`, custom scrollbars, refined base layer (border-radius, font stack). Remove the hardcoded `color-scheme: dark` from `:root`.

2. **`index.html`** — add a one-line inline pre-paint script in `<head>` that reads `localStorage('composa-theme')` (defaulting to `prefers-color-scheme`) and sets/removes `.dark` on `documentElement` before first paint (no FOUC). `lang="en"` already present.

3. **`src/state/theme.ts`** *(new, ~40 lines)* — `getTheme()`, `setTheme()`, `toggleTheme()` over module-level state + `useSyncExternalStore`-backed `useTheme()` hook. Reads/writes `localStorage('composa-theme')`, applies/removes `.dark` on `document.documentElement`. (`use-sync-external-store` is already a dep.)

### Token migration (9 components — class swaps only, structure untouched)

Replace every `slate-*`/`blue-*`/`red-*`/`amber-400` class with the matching semantic token. Verified color-class inventory: ~110 occurrences across these 9 files.

### Risk
Low. `@theme inline` + CSS-var tokens is the documented v4 pattern. The only non-class change is the boundary-rect SVG `stroke` becoming a CSS-var reference (valid for SVG attributes). Verified the 190 unit + 6 e2e specs assert on behavior/data-testids only, never colors or classes — so they pass unchanged. The redesign *improves* contrast (WCAG AA targets met for text-on-surface and text-on-primary).
